# ZSH-043: Fixed percentage heights do not deliver the documented short-terminal guarantee

| Field | Value |
| --- | --- |
| Status | Open |
| Priority | P2 — user-facing documentation states a guarantee the geometry does not provide, and the fixed heights change every picker's frame, including non-preview finders |
| Audit date | 2026-10-01 |
| Audited baseline | c052f7a52ea1f1cb088de1fd30dc22e724491551 |
| Affected surface | All fzf entry points that inherit the shared frame (`Ctrl-R`, `Ctrl-T`, `Alt-C`, completions, `fbr`, and other preview pickers) |
| Evidence | fzf(1) minimum-height semantics plus PTY frame measurements on fzf 0.74.4 during the review audit |

## Summary

[GUIDE.md](../../GUIDE.md#finder-layout-and-option-precedence) states that "fixed percentage heights keep room for selectable rows when a preview opens or moves below the list, including one- and two-item pickers", and [README.md](../../README.md) repeats "fixed percentage heights that keep short lists visible". Measured behavior contradicts the attribution and the unconditional claim: fzf treats a percentage `--height` as a lower bound subject to `--min-height` (default `10+`, which auto-increases so the configured number of items stays visible), so on short terminals the rendered frame is larger than the percentage (58% and 88% observed instead of 45%/60%), and at 12 rows the frame fills the screen. Conversely, pinning the height stops one- and two-item pickers from hugging their content. The same fixed heights are exported through `FZF_DEFAULT_OPTS`, so `Ctrl-R`, `Ctrl-T`, `Alt-C`, and completion pickers inherit them even though the documented claim only concerns the preview case.

## Affected code and documentation

- [25-theme.zsh](../../25-theme.zsh): `_zsh_theme_fzf_chrome_args` (lines 261–267) emits `--height=60%`, `80%`, and `45%` for compact, roomy, and minimal. Before this change, compact and minimal used adaptive values (`~60%`, `~45%`); roomy was already fixed at `80%`.
- [40-fzf.zsh](../../40-fzf.zsh): `_fzf_export_config` builds `FZF_DEFAULT_OPTS` from the chrome options (lines 71–76), so every default finder inherits the fixed height.
- [GUIDE.md](../../GUIDE.md#finder-layout-and-option-precedence): line 237 makes the unconditional claim; the table at lines 231–235 describes the layouts.
- [README.md](../../README.md): line 44 repeats the claim.
- [scripts/test-theme.zsh](../../scripts/test-theme.zsh): lines 184 and 200 assert only `--height=[0-9]*%` (format, not value), so any percentage passes.
- [scripts/test-fzf-pty.py](../../scripts/test-fzf-pty.py): no case asserts actual frame height or list visibility at short terminal sizes.

## Trigger and reproduction

Use the repository's own picker arguments in a PTY at 24, 16, and 12 rows with each layout, and with a one- or two-item list. The review audit used the shared args from `25-theme.zsh`/`40-fzf.zsh` on fzf 0.74.4 and measured the drawn frame and list rows:

| Terminal rows | Layout | Documented height | Measured frame |
| --- | --- | --- | --- |
| 24 | minimal | 45% | 14 rows (58%) |
| 16 | compact / minimal | 60% / 45% | 14 rows (88%) |
| 12 | any | percentage | frame fills the screen and overwrites scrollback |

With a below-list preview and a short list, a visible list row appeared only from `LINES=9` (one item) and `LINES=10` (two items). For content hugging, a one-item picker at width 120 drew a 14-row frame with the fixed 60% height versus 7 rows with the previous adaptive value.

Independently confirmed mechanism: fzf(1) `--min-height=HEIGHT[+]` — "Minimum height when `--height` is given as a percentage … (default: `10+`)" and `+` increases the value "so that the specified number of items are visible in the list section".

## Current behavior and impact

The documented "fixed percentage heights" guarantee is not what keeps short lists visible — fzf's minimum-height behavior is — and on short terminals the frame exceeds the stated percentage, can fill a 12-row screen, and overwrites scrollback. Every picker that inherits `FZF_DEFAULT_OPTS` draws the fixed height even for one-item lists, removing the previous content-hugging behavior. The theme regression only checks the option's shape, so none of this is caught.

## Root cause

`_zsh_theme_fzf_chrome_args` emits a fixed percentage height, and `_fzf_export_config` exports it as the default for all finders. fzf interprets the percentage as a lower bound and raises it via `--min-height` whenever the list would otherwise lose rows, so the rendered geometry depends on terminal rows, borders, and list size rather than the number in the option. The documentation attributes short-list visibility to the fixed percentage and states it without terminal-size conditions; the tests assert only the option format.

## Fix goal and expected behavior

- Decide and implement one policy, then make documentation and tests match it:
  - keep percentage heights and document the actual behavior at short terminals (minimum-height interaction, 12-row behavior), or
  - restore adaptive heights and pin `--min-height=N+` explicitly where short-list visibility is required (the review measured that the corrected threshold alone keeps 1–2-item lists visible with adaptive heights, so the fixed-height change is not required to resolve ZSH-041).
- Short lists must stay visible with the preview open or below the list on supported terminal sizes, and one- and two-item pickers should either hug their content again or the deliberate non-hugging must be documented.
- `Ctrl-R`, `Ctrl-T`, `Alt-C`, and completion pickers must not regress from the exported height choice.

## Implementation constraints

- Preserve option composition order and inherited-layer precedence documented in GUIDE.md.
- Keep `NO_COLOR`, custom color, glyph, and layout handling intact; `ztheme` session switching must remain atomic.
- Support fzf 0.68.0 and 0.74.3+; keep startup pure Zsh with no probes or terminal queries in `25-theme.zsh`.
- Synchronize README.md, GUIDE.md, and any affected tips text with the chosen policy.

## Acceptance criteria

- [ ] A PTY case proves at least one selectable row is visible for one- and two-item lists with the preview open at a short terminal size.
- [ ] `scripts/test-theme.zsh` asserts the per-layout height values, not just the option format, so flattening all layouts fails.
- [ ] Non-preview pickers (`Ctrl-R`, `Ctrl-T`, `Alt-C`, completions) are checked with the exported defaults for oversized frames.
