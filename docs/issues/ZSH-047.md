## Summary

Each `fbr-<layout>-normal` case drives the picker against a fixture that is already on the branch it selects (`main`), and then asserts `RESULT_CWD` is the fixture and `RESULT_HEAD` is `main`. Those are exactly the values that hold if `fbr` ignores the accepted selection entirely and changes nothing, so the case cannot detect regressions in the `--accept-nth` mapping or activation for the current-branch row. The suite's worktree and cancel cases do verify real transitions; only the canonical normal-selection path is unverified. In addition, [GUIDE.md](../../GUIDE.md#required-checks) line 915 still describes the suite as covering "50/100-column terminals, Unicode/ASCII, `NO_COLOR`, preview toggling, multi-selection, and cancellation", while the suite now runs 43 cases including three layouts, widths 50/80/110/120, one- and two-row fixtures, live resize, and worktree/normal/cancel flows.

## Affected code and documentation

- [scripts/test-fzf-pty.py](../../scripts/test-fzf-pty.py): `run_branch_case` expectations (lines 480–510) and the `normal` invocation (line 556). The fixture stays on `main` while `qa-topic` exists in a worktree (lines 428–437); the query typed for `normal` is `main` (line 481).
- [GUIDE.md](../../GUIDE.md#required-checks): line 915 describes the PTY coverage with pre-change detail.
- [README.md](../../README.md): if the summary links to that coverage, keep its wording consistent.

## Trigger and reproduction

Prerequisites: this checkout and native fzf. Reasoning-level reproduction: mutate `_fbr_activate` ([lib/functions-git.zsh](../../lib/functions-git.zsh), line 82) so activation is skipped for a row that matches the current branch, or replace the accepted value with an empty string, and run the `normal` cases — the suite still passes because the expected cwd/head already hold. A runnable demonstration would select a branch other than the checked-out one (for example query `qa-topic` and expect the worktree path) in a disposable fixture; the worktree cases already do this, which is why only the normal case is weak.

```text
fbr fixture (rows=2): HEAD=main, branches: main + [WT] qa-topic
normal case: query "main", Enter -> expected cwd=<fixture>, head=main
no-op path:  query "main", Enter -> cwd=<fixture>, head=main (indistinguishable)
```

No package manager, credentials, or live repository state is used; fixtures are temporary directories.

## Current behavior and impact

The suite advertises canonical-branch selection coverage it does not have; a regression in accepting the already-current branch (accept-nth mapping, activation guard, cleanup after selection) passes all `normal` cases. The stale GUIDE paragraph compounds this by misstating what CI verifies, so maintainers cannot tell which behaviors are actually protected.

## Root cause

The case was written for rendering/live-resize coverage (its assertions are strong there) and reuses the checked-out branch for the `normal` flow; the expected post-selection state coincides with the no-op state. The verification paragraph was not updated when the suite grew from the original 4-case shape to the current layout/width/row matrix.

## Fix goal and expected behavior

- The normal-selection case must distinguish acceptance from a no-op: select a branch that differs from the checked-out one (and assert the resulting head, keeping a separate current-branch case only if it asserts an observable activation effect), or assert an effect that cannot hold when activation is skipped.
- Keep the existing rendering, resize, worktree, and cancellation assertions unchanged.
- GUIDE.md must describe the suite's actual coverage (layouts, widths, fixtures, resize, normal/worktree/cancel) without overstating.

## Implementation constraints

- Fixtures stay disposable; no real package operations or credentials.
- Keep the suite stdlib-only and passing on fzf 0.68.0 and 0.74.3+.
- Keep per-case HOME isolation (see completed ZSH-046 in Git history for the remaining isolation gap).

## Acceptance criteria

- [ ] A mutation that makes `fbr` ignore the accepted selection fails the normal case.
- [ ] The worktree and cancel cases retain their current transition assertions.
- [ ] GUIDE.md line 915 matches the suite's actual case inventory and coverage.
- [ ] `python3 scripts/test-fzf-pty.py` passes on both supported fzf versions and `zsh scripts/run-tests.zsh` passes.

## Validation plan

Rework the normal case against a disposable fixture, add the mutation check manually during repair, update the GUIDE paragraph, and run the suite on both supported fzf versions plus the required `zsh scripts/run-tests.zsh`; obtain subagent review under the issue repair workflow.
