# ZSH-041: Wide adaptive branch pickers hide every row while preview is open

## Summary

With a two-branch repository, a 110- or 120-column terminal, and compact or minimal layout, `fbr` opens a small frame with its search input, match counter, footer, and Git preview but no visible branch rows. Filtering and selection still operate on invisible choices. Ctrl+P reveals the rows by hiding the preview; roomy layout also shows them. Both supported fzf versions reproduce the problem.

## Trigger and reproduction

Use an isolated installation HOME, the documented standalone `compinit` setup, no inherited finder overrides, and a UTF-8 `xterm-256color` terminal with 32 rows and 110 columns. Install native fzf 0.68.0 or 0.74.3. Create only disposable Git state:

```sh
git init -b main /tmp/zsh-picker-fixture
git -C /tmp/zsh-picker-fixture -c user.name=QA \
  -c user.email=qa@example.invalid commit --allow-empty -m initial
git -C /tmp/zsh-picker-fixture branch qa-topic
git -C /tmp/zsh-picker-fixture worktree add /tmp/zsh-picker-worktree qa-topic
```

Use fresh, unused fixture paths. In the interactive shell:

```zsh
unset NO_COLOR
ZSH_FZF_LAYOUT=compact
ztheme use terminal
cd /tmp/zsh-picker-fixture
fbr
```

Observe the frame, `2/2` counter and preview but no branch list. Press Ctrl+P: `main` and `[WT] qa-topic` become visible. Escape, then repeat with `ZSH_FZF_LAYOUT=minimal; ztheme use terminal`. Repeat with roomy as the passing comparison. Do not select a branch unless operating entirely inside the fixture.

Native probes captured initial output before typing any filter and separately captured the redraw after hiding preview. `[WT]` is a row-only sentinel absent from `git log`, so the preview cannot satisfy the visibility check. Each probe uses a controlling PTY, terminal-query responses, isolated HOME/cache, and owned process cleanup.

| fzf versions | Terminal width | Layout | Initial worktree row | After hiding preview |
| --- | --- | --- | --- | --- |
| 0.68.0 and 0.74.3 | 50, 80 | compact, minimal, roomy | Visible | Visible |
| 0.68.0 and 0.74.3 | 110, 120 | compact, minimal | Absent | Visible |
| 0.68.0 and 0.74.3 | 110, 120 | roomy | Visible | Visible |

## Current behavior and impact

Users cannot inspect branch labels, worktree badges, age, or subjects before accepting a choice. The picker still counts and filters the underlying branches; a manually filtered `qa-topic` selection entered its correct disposable worktree even while the list was invisible. This is a rendering failure, not incorrect Git identity selection. The existing four native picker checks pass, demonstrating that they do not cover this short-list, wide-preview combination. Other preview pickers sharing these options require validation; this report does not claim they all reproduce it.

## Root cause

Compact and minimal use adaptive `--height=~60%` / `~45%` together with input/header/footer separators and a responsive percentage preview. The wide-terminal preview option includes `right,...,<100(down,...)`. In this short-list combination the resulting geometry leaves no visible list rows while the preview remains open. Removing the preview restores them without changing the data; fixed-height roomy mode avoids the failure. The precise fzf internal allocation should be checked during repair rather than assuming row generation is broken.

## Fix goal and expected behavior

Every nonempty picker must retain at least one visible selectable row with its normal preview open. Two-row branch fixtures should display both rows when space permits. Keep responsive previews, useful compact/minimal sizing, and correct worktree selection. Ctrl+P must remain an optional presentation control instead of a prerequisite for discovering choices.

## Implementation constraints

- Support fzf 0.68.0 and 0.74.3 without silently raising the minimum version.
- Preserve canonical branch refs, undecorated selection identities, shell quoting, worktree guards, and preview safety.
- Preserve inherited option precedence, NO_COLOR, glyph tiers, and atomic session theme switching.
- Keep startup lightweight; do not add terminal queries or executable probes to theme startup.
- Synchronize relevant README/GUIDE/tips surfaces when user-facing layout behavior changes.

## Acceptance criteria

- [ ] With one and two branches at 110 and 120 columns, compact/minimal render selectable rows before Ctrl+P on both supported fzf versions.
- [ ] Visible row assertions distinguish actual list labels/badges from text echoed by commands or previews.
- [ ] Verify narrow/wide terminals, roomy layout, plain/color output, and preview hide/show after filtering.
- [ ] Worktree and normal branch selection, Escape cancellation, and queued shell state retain their documented effects.
- [ ] Check short lists in other shared preview pickers and prevent recurrence where the same geometry applies.
