# ZSH-045: Children-list parsing follows the caller's IFS and bypasses the launcher fallback

| Field | Value |
| --- | --- |
| Status | Open |
| Priority | P2 — a common `IFS` setting silently disables the fallback added for ZSH-040 and lets a failed-startup supervisor survive cleanup |
| Audit date | 2026-10-01 |
| Audited baseline | c052f7a52ea1f1cb088de1fd30dc22e724491551 |
| Affected surface | Captured upkg query failed-startup cleanup (`_zsh_query_task_children` and its caller) |
| Evidence | Source inspection and Zsh word-splitting checks on the audited baseline |

## Summary

`_zsh_query_task_children` splits the optional children file with `${=text}`, which uses the caller's `IFS` instead of the shell default. With `IFS=$'\n'` — a common idiom — a space-separated children list such as `95359 95361 ` yields a single element that is not a valid PID. The helper still returns `0` because its reply is non-empty, so the caller takes the success path and its numeric guard (`[[ $child == <-> ]]`) silently skips the unusable element; the process-stat fallback never runs. A detached query supervisor and its child then survive the failed-startup cleanup, which is the same leak class ZSH-040 removed, and the caller still reports the failure status and removes the control directory. The dependence on the caller's `IFS` predates this change (the previous helper used the same `${=...}` split), but this work rewrote the helper around a success/reply contract that the IFS bypass defeats, so it should pin its own parsing.

## Affected code and documentation

- [lib/functions-common.zsh](../../lib/functions-common.zsh): `_zsh_query_task_children` (baseline lines 352–364; the split is line 361). Its caller is `_zsh_stop_unidentified_launcher` (376–389), where the fallback is chosen by the helper's return status and unusable elements are skipped at line 389.

## Trigger and reproduction

Prerequisites: a shell that invokes a captured query with `IFS=$'\n'` (or any IFS that does not contain a space), GNU/Linux `/proc`, Zsh 5.9. Setup is synthetic: a launcher whose child list is non-empty, and a failed identity handshake as in [scripts/test-query-ownership.zsh](../../scripts/test-query-ownership.zsh).

Word-splitting check on the audited shell:

```zsh
zsh -f -c 'text="95359 95361 "
children=( ${=text} ); print -r -- "default IFS: count=${#children[@]} first=[$children[1]]"
IFS=$'"'"'\n'"'"'
children=( ${=text} ); print -r -- "IFS=newline: count=${#children[@]} first=[$children[1]]"'
```

```text
default IFS: count=2 first=[95359]
IFS=newline: count=1 first=[95359 95361 ]
```

With `IFS=$'\n'`, the helper appends one element, returns `0`, the caller's `[[ $child == <-> ]]` guard skips it, `_zsh_stop_unidentified_launcher` never enters the `/proc` fallback, and the supervisor and its child remain alive. The review audit verified this flow end to end before the ownership suite's `check_gone` would otherwise fail; the current suite cannot catch it because the missing/unreadable modes replace the helper.

## Current behavior and impact

A user with `IFS=$'\n'` set (for example while looping over lines) runs captured package queries with cleanup silently degraded to "no children discovered"; the failed-startup path still returns `1` with the normal diagnostic, so nothing surfaces the leak. Depending on the abandoned command, work continues after the shell reports failure. This is a diagnostic-free path to the process leak that ZSH-040 was raised for.

## Root cause

`${=text}` performs IFS-based word splitting using the caller's `IFS`; `emulate -L zsh` resets options, not parameters, so the helper inherits whatever the invoking scope set. The helper's implicit contract — non-zero status or no usable reply means "discovery failed" — is not enforced: a non-empty array of unusable elements returns `0`, and the caller treats any successful return as authoritative and only skips elements it cannot parse.

## Fix goal and expected behavior

- The helper must parse the children file deterministically regardless of the caller's `IFS` (for example `local IFS=$' \t\n'`, or an explicit `read`/`(f)` loop), and it must return a non-zero status when no usable numeric child IDs were found.
- The caller must fall back to process-stat discovery whenever the fast path yields no usable IDs, not only when the helper reports failure.
- The helper's contract must be documented by direct tests of the real function, not only by mocks that copy its internals.
- Cleanup must complete for the failure modes already covered by ZSH-040 under any caller `IFS`.

## Implementation constraints

- Keep discovery read-only: PPID establishes candidates, never permission to kill.
- Preserve the fast per-task path, the readable-file guard, and the bounded fallback behavior; do not change signalling semantics (see [ZSH-044](ZSH-044.md)).
- Keep the helper in the trusted lazy module with the existing loading path.
- Synchronize GUIDE.md if any user-visible cleanup wording changes.

## Acceptance criteria

- [ ] A regression case with `IFS=$'\n'` and a space-separated children file runs the real helper, engages the fallback, and leaves no surviving launcher or child.
- [ ] Malformed or empty children content (non-numeric tokens, partial writes, trailing separators) never returns a success status that suppresses the fallback.
- [ ] `scripts/test-query-ownership.zsh` asserts the fallback actually ran (for example via a marker or by observing the discovered process), rather than redefining the helper.
- [ ] Existing ownership modes keep their statuses and diagnostics; `zsh scripts/run-tests.zsh` passes.
