# ZSH-044: Launcher cleanup can abandon stopped processes and signal unverified PIDs

| Field | Value |
| --- | --- |
| Status | Open |
| Priority | P2, blocking — cleanup can leave a process stopped indefinitely and can signal a PID whose identity is no longer verified; not P1 because the abandonment window is a few syscalls wide and needs fault injection to reproduce |
| Audit date | 2026-10-01 |
| Audited baseline | c052f7a52ea1f1cb088de1fd30dc22e724491551 |
| Affected surface | Captured upkg query failed-startup cleanup (`_zsh_stop_unidentified_launcher`) |
| Evidence | Source inspection against the pre-PR revision plus a fault-injection PTY-free reproduction on GNU/Linux, Zsh 5.9 |

## Summary

`_zsh_stop_unidentified_launcher` freezes the launcher, discovers its children, and now freezes each child before re-verifying it. If a re-verification guard fails — an unreadable stat file, or a child that was reparented or reused after the frozen launcher died — the loop executes `continue` and leaves that child in the `T` (stopped) state forever: no path sends `SIGCONT` or a kill after abandoning it. The old implementation never stopped children, so this is a new failure mode. Separately, the final launcher termination re-reads `/proc/<pid>/stat` without the parent/start-time verification the child path performs, and the newly added whole-`/proc` fallback scan widens the window between discovery and that kill, so a reaped launcher's PID can be signalled after recycling. [GUIDE.md](../../GUIDE.md#results-and-exit-status) already promises that "every candidate is checked against its parent and start time before signalling"; the final path does not honor it.

## Affected code and documentation

- [lib/functions-common.zsh](../../lib/functions-common.zsh): `_zsh_stop_unidentified_launcher` (baseline lines 367–411). Launcher freeze at 375; whole-`/proc` fallback scan at 380–386; child freeze at 394; abandonment points at 389, 391, 395, and 397; final unchecked re-read and kill at 404–408. `_zsh_query_task_children` (352–364) supplies the fast path.
- [scripts/test-query-ownership.zsh](../../scripts/test-query-ownership.zsh): the final `direct`/`fork`/`fork-missing-children`/`fork-unreadable-children` cases exercise cleanup but none of them kills the launcher mid-cleanup.
- [GUIDE.md](../../GUIDE.md#results-and-exit-status): line 847 states the verification guarantee for failed-startup cleanup.

## Trigger and reproduction

Prerequisites: GNU/Linux with readable proc stat files, Zsh 5.9, util-linux `setsid`, no package manager or credentials involved. The reproduction uses a synthetic launcher (`zsh -c 'sleep 300 & wait'`) with one `sleep` child and a driver that sources a test copy of `lib/functions-common.zsh` with a 0.5 s delay injected after the child freeze (line 394) to widen the race; this host reports no `/proc/<pid>/task/<tid>/children` files, so the process-stat fallback path runs. A watcher kills the launcher (`SIGKILL`) as soon as the child reports state `T`, then the driver calls `_zsh_stop_unidentified_launcher <launcher> <identity> <parent>` with the real start-time identity.

Observed:

```text
launcher=147388 parent=147385 child=147390 identity=737665
watcher: killed launcher while child in T state
_zsh_stop_unidentified_launcher:38: no such file or directory: /proc/147388/stat
after cleanup: child state=T ppid=1230
after 0.3s: child state=T ppid=1230
```

The function returned normally, the child stayed stopped with a reparented PPID, and nothing ever resumed or killed it. The same shape is reachable when the stat read at line 395 fails, and the review audit reproduced it by the same window-widening method. Without injected delay the window is only a few syscalls wide, so normal runs rarely hit it; any external `SIGKILL` (user, service manager, OOM) to the frozen launcher inside that window converts it into a permanent stopped process.

For the final kill: if the frozen launcher is reaped while the fallback scan or the final read runs, `stat_text` is empty, the identity comparison cannot pass, and line 408 sends `SIGKILL` to the unchecked PID. The demo above shows the read failing with a shell diagnostic and the `kill -KILL` branch being taken on the dead launcher; had the PID been recycled in that interval, an unrelated process would have been killed.

## Current behavior and impact

A child that fails re-verification is left in `T` state indefinitely, holding file descriptors and any resources it acquired; the failed-startup path still returns status `1` and removes the private control directory, so the leak is silent. The launcher kill path can signal a process it has not verified. Both are cleanup contract violations; neither was possible for children before this change because the old code killed children directly without stopping them.

## Root cause

The freeze-for-inspection step (launcher at 375, each child at 394) is not paired with a recovery guarantee: every post-freeze guard that can fail exits with `continue`, and no code path tracks which processes were stopped. The same stat parse-and-verify idiom is duplicated inline at several points, and the final launcher path omits the identity checks entirely. The new `/proc` fallback scan (an O(all PIDs) read-and-parse while the launcher is stopped) extends the interval during which the launcher can be reaped before the unchecked kill.

## Fix goal and expected behavior

- No failure path may leave a process stopped: before any `continue` after a freeze, resume (`SIGCONT`) or kill the process, or restructure so freezes happen only where the following kill cannot be skipped.
- Every signal must be gated on parent and start-time verification, including the final launcher kill, so the GUIDE sentence is true.
- Keep the read-only discovery policy: PPID establishes candidates, never permission to kill.
- Keep the fast per-task child-list path and a bounded fallback; do not make cleanup proportional to the whole process table when a cheaper verified path exists.
- Preserve return statuses and diagnostics of the failed-startup flow.

## Implementation constraints

- Follow the guard rules in [AGENTS.md](../../AGENTS.md): function bodies use `command -v`, startup paths use `$commands`.
- Do not change ownership semantics, session handling, or the supervisor contract; keep ZSH-040's fixes intact.
- Keep the helper lazy-loaded; no new dependencies beyond util-linux/Zsh modules already required.
- Update GUIDE.md only where behavior text changes; the verification sentence must become accurate.

## Acceptance criteria

- [ ] A fixture that reparents or reuses a child between freeze and re-verification asserts the process is not left in `T` state (resumed or gone).
- [ ] A fixture that kills the launcher during fallback discovery asserts no signal is sent to an unverified/recycled PID (identity-checked kill or none).
- [ ] A fixture with an unreadable stat file during the child loop asserts no stopped process remains.
- [ ] Existing ownership modes (missing/unreadable children files, missing identity, owner loss) still terminate within budget and return documented statuses.
- [ ] `zsh scripts/run-tests.zsh` passes.
