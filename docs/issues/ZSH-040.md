# ZSH-040: Failed query startup leaves forked supervisors alive without proc child lists

| Field | Value |
| --- | --- |
| Status | Open |
| Priority | P1 — owned process cleanup fails and the required regression runner exits nonzero |
| Audit date | 2026-10-01 |
| Audited baseline | b1cb5e554dcdb2aa0c31322bdf07722061269d32 |
| Affected surface | Captured upkg queries and Nix query supervision |
| Evidence | Repeated synthetic startup-failure reproduction on GNU/Linux, Zsh 5.9 |

## Summary

A forked query supervisor that never publishes its startup identity survives the caller's failed-startup cleanup when `/proc/<pid>/task/<tid>/children` is unavailable. Its child survives too. The caller returns status 1 and removes its private storage while the detached session continues running. The current prerequisite check accepts this environment because `/proc/<pid>/stat` and `setsid` are available.

## Trigger and reproduction

Prerequisites: GNU/Linux with readable proc stat files but unavailable per-task `children` files, Zsh 5.9, util-linux `setsid`, and normal unprivileged execution. No package manager or credential backend is invoked.

Confirm the process-interface distinction in the same environment:

```sh
python3 - <<'PY'
import os
from pathlib import Path
pid = os.getpid()
print('stat available:', Path(f'/proc/{pid}/stat').is_file())
print('children available:', Path(f'/proc/{pid}/task/{pid}/children').is_file())
PY
zsh scripts/test-query-ownership.zsh
```

Observed: `stat available: True`, `children available: False`; the ownership suite exits 1. The final output is:

```text
ok: failed completion publication terminates and retains captured data
ok: direct missing identity shuts down within its startup budget
not ok: abandoned process remained alive
```

The suite's last fixture wraps `setsid` with `--fork`, starts a synthetic supervisor that ignores TERM and never writes the control-directory identity, and records that supervisor and a `sleep` child independently. An instrumented copy outside the checkout confirmed `mode=fork`: after the caller returned, both recorded processes were non-zombies, the supervisor had PPID 1 and remained its own process-group/session leader. The suite's EXIT cleanup subsequently killed its recorded groups. This was reproduced in standalone and full-runner invocations; ordinary owner-loss and direct-launch cases passed.

## Current behavior and impact

The caller emits `Captured package query supervisor did not establish its identity.` and returns 1, but the supervisor and its descendant remain alive. Query cleanup therefore fails under this documented GNU/Linux prerequisite set. Depending on the abandoned command, work can continue after the shell has reported failure. The reproduced fixture proves process leakage, not a live package mutation or data loss. The required release regression also stops before its later suites.

## Root cause

The preflight only validates proc stat access and `setsid`. Cleanup freezes the launcher, then enumerates `/proc/$pid/task/*/children(N)`. If those files do not exist, the null glob yields no iterations. Cleanup kills the launcher and returns success without discovering or stopping the detached session it forked. The normal supervisor's owner-death protection cannot help a supervisor that failed before installing that protection or publishing its identity.

## Fix goal and expected behavior

Failed startup must leave no owned running supervisor or descendant. Either support identity-checked child discovery when the per-task interface is unavailable, or reject the unsupported supervision environment before starting any query. If rejecting it, explain the missing prerequisite clearly and keep failure status nonzero. Preserve the normal bounded handshake, captured streams, and ownership protections.

## Implementation constraints

- Never replace identity checks with broad `pkill`, `killall`, or unverified process-group signalling.
- Preserve PID/start-time, parent, session/group identity checks and protection of unrelated jobs/storage.
- Keep queries Linux-specific, lazy-loaded, bounded on startup, and confined to private storage.
- If prerequisites change, synchronize the dependency checker and appropriate README/GUIDE/help/tips surfaces under [AGENTS.md](../../AGENTS.md).
- Reproduce with synthetic processes; do not use native upgrades, cleanup, or real credentials.

## Acceptance criteria

- [ ] On a host without per-task child files, a forked missing-identity startup either is refused before launch or terminates every owned running descendant.
- [ ] Direct and forked startup failures return nonzero within a bounded deadline and explain the failure.
- [ ] Missing/unreadable child discovery is explicitly tested rather than treated as an empty child list.
- [ ] Unrelated processes and directories remain untouched; successful query output/status remain correct.
- [ ] All existing owner-loss, cancellation, publication-failure, and ownership regressions pass.
